# CLAUDE.md

Letter Bridge: a word game (type a word that starts and ends with the given letters before the timer runs out). Solo play plus live multiplayer rooms. See README.md for the full overview and folder layout.

## Commands
- `npm test`: run unit tests. **Never `npx vitest` directly**: on Windows a lowercase drive letter (`c:\…`) makes Vitest crash; `scripts/run-tests.mjs` fixes it. Filter with `npm test -- room`.
- `npx tsc --noEmit`: typecheck the app. `npm run party:check`: typecheck the room server (separate tsconfig, Cloudflare types).
- `npm run lint`, `npm run build`.
- After adding or renaming a route, run `npx next typegen` so `PageProps<"/…">` types exist.
- Local multiplayer needs **two** servers: `npm run dev` + `npm run party:dev` (port 8787). For phones on the same Wi-Fi: `npm run dev:lan` + `npm run party:dev:lan`.
- Only one `next dev` can run per project. For a second server (e.g. browser tests while the user's dev server runs), use `next build && next start -p <port>`.

## Architecture rules
- `src/lib/game` and `src/lib/multiplayer` are **pure TypeScript**: no React, no browser APIs, no clock, no `Math.random` in reducers. Time comes in as `now`, randomness as a seed or `rng` parameter. The Cloudflare room server imports this code unchanged, so keep it pure.
- Inside `src/lib/`, use **relative imports**, not `@/…`: wrangler bundles these files too.
- State changes go through reducers (`gameReducer`, `roomReducer`). Every rule change gets a unit test in `tests/`.
- `party/server.ts` stays thin: identity (secret token → public player id), messages, broadcasting, the clock. All decisions live in `src/lib/multiplayer/room.ts`.
- Multiplayer answers are checked instantly in the browser **and** again on the server; the server's verdict is final. Every player gets the same pairs from the shared seed (`pairForRound` in `lib/game/random.ts`).
- Every message from the network is validated (`parseClientMessage`, `parseConnectionQuery`) before use.
- Tunable numbers live in `lib/game/config.ts` / `lib/multiplayer/config.ts`, never hard-coded.

## Gotchas (Next.js 16 + this setup)
- This Next.js version differs from older ones: read `node_modules/next/dist/docs/` before relying on memory. `AGENTS.md` is generated by `next dev`; leave it alone.
- `cacheComponents` is on: navigating away **hides** a page (React `<Activity>`) instead of unmounting it, so its state survives. Reset state that shouldn't persist in a `useLayoutEffect` cleanup (see `src/app/solo/page.tsx`).
- Dynamic route params (e.g. `/room/[code]`) must be read inside `<Suspense>`.
- Lint rule `react-hooks/set-state-in-effect`: don't call `setState`/`dispatch` synchronously in an effect body. Use event handlers, lazy initial state, or effect cleanups.
- partysocket replays queued messages on reconnect, so identity is sent in the connection URL (`?token=…&name=…`), not as a message.

## Deployment
- Game: Vercel, auto-deploys on push to `main`.
- Room server: Cloudflare Durable Object, `npm run party:deploy` (`wrangler.jsonc`). Redeploy it whenever `party/`, `src/lib/`, or `data/` changes, so server and site stay in sync.
- `NEXT_PUBLIC_PARTY_HOST` = the room server's host **without** `https://`. It's baked in at build time, so changing it needs a Vercel redeploy.
- Don't run `wrangler login` / `party:deploy` or publish anything without the user asking.

## Style
- Every file starts with a header comment explaining **what** it is and **why**, in plain language a beginner can follow. Match that in new files and keep comments up to date.
- Design tokens: see DESIGN.md. Use the theme classes from `globals.css` (`bg-ink`, `rounded-card`, `text-tile`…) rather than raw hex or one-off sizes.
- UI uses the shared pieces in `src/components/ui.tsx` (`ScreenHeader`, `SectionHeading`, `Button`, `LinkButton`, `BackLink`, `CHOICE_KEY`, `LIST_CARD`, `INPUT_BASE`). Type scale: one hero number, one 40px `ScreenHeader` title per screen (slab `text-display`), big slab headlines (`text-headline`, sentence-case `text-section` section headings). Emerald (`accent`) for the main action and good news, red (`danger`) only for problems. Check light and dark mode at phone width (~390px).
- Solo and multiplayer share game components (`PlayingScreen`, `useGame`). Don't fork them.
